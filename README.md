# gh-star-reader

スターしたリポジトリを、読んでいない本の山として並べ直すツールです。

GitHub のユーザー名を入れると、スターした順に一覧が並びます。項目を開くと、
そのリポジトリで使われている技術、設計上の工夫、そしてどのファイルから
読み始めればいいかを要約します。

「スターは付けたけれど、結局一度も開いていない」を減らすことが目的です。

## できること

- スター一覧を、スターした日の古い順に並べる
- スター全体の言語構成を 1 本のバーで表示（リポジトリ 1 件を等しい重みで数えるので、
  巨大なリポジトリ 1 つに引きずられません）
- バーの言語を押すと、その言語を最もよく使うリポジトリだけに絞り込み
- 未読のみ / 並び順での絞り込み
- 開いたリポジトリの要約
  - **使用技術** — 言語構成、フレームワーク、主要な依存
  - **設計上の工夫** — 構成や方針から読み取れること
  - **読む順序** — 最初に開くべきファイルと、その理由
- 読了の記録

小規模なリポジトリでは README や依存関係だけでなく、実際のソースコードも
読んだうえで要約します。個人の実験リポジトリのように小さいものほど全体が
文脈に収まるので、むしろ要約の質は上がります。

## セットアップ

```bash
git clone https://github.com/<your-account>/gh-star-reader.git
cd gh-star-reader
npm install
cp .env.example .env.local   # 値を記入する
npm run dev
```

```bash
npm run typecheck   # 型チェック
npm test            # src/lib のテスト
```

http://localhost:3000 を開いてください。

## 環境変数

| 変数 | 必須 | 用途 |
| --- | --- | --- |
| `GITHUB_TOKEN` | 推奨 | GitHub API 用の Personal Access Token。**スコープは不要**（公開データしか読まないため、無スコープで発行して構いません）。未設定でも動きますが 60 リクエスト/時、設定すると 5,000 リクエスト/時になります |
| `LLM_API_KEY` | 必須 | 要約の生成に使用 |
| `LLM_BASE_URL` | 任意 | 既定は Google AI Studio |
| `LLM_MODEL` | 任意 | 既定は `gemini-3.6-flash` |
| `ALLOW_PRIVATE_REPOS` | 任意 | プライベートリポジトリの要約を許可する。既定は無効 |
| `TURSO_DATABASE_URL` | 任意 | 既定はローカルファイル `file:./.data/gh-star-reader.db`。デプロイ時は Turso の `libsql://…` |
| `TURSO_AUTH_TOKEN` | Turso 使用時 | Turso のトークン。ローカルファイルでは不要 |
| `ADMIN_TOKEN` | 招待管理時 | 招待の発行・失効に使う。未設定なら管理 API は無効 |
| `BASE_URL` | 任意 | `npm run invite` の接続先。既定は `http://localhost:3000` |
| `DEV_ORIGINS` | 任意 | 開発サーバーを LAN アドレスで開くときのホスト（カンマ区切り）。下記参照 |
| `INVITE_REQUIRED` | 任意 | 招待リンクを必須にする。既定は本番ビルドで有効、開発で無効 |

いずれもサーバー側でのみ読みます。ブラウザには渡りません。

### LAN の別端末から開く場合

`next dev` は起動元のオリジン以外からの `/_next/*` の取得を 403 で拒みます。
`http://192.168.0.7:3001` のように LAN アドレスで開くとチャンクが 1 つも
読めず、画面は出るのにボタンが一切反応しません（コンソールに 403 と
WebSocket のハンドシェイク失敗が並びます）。そのホストを許可してください。

```bash
DEV_ORIGINS=192.168.0.7
```

変更後は開発サーバーの再起動が必要です。`localhost` で開く分には要りません。

## モデルの提供元

OpenAI 互換の chat-completions エンドポイントなら何でも使えます。既定は
Google AI Studio の無料枠です。

| 提供元 | `LLM_BASE_URL` | 備考 |
| --- | --- | --- |
| Google AI Studio | `https://generativelanguage.googleapis.com/v1beta/openai` | 無料枠。Flash 系のみ。入力枠が大きくソース読解に耐える |
| Groq | `https://api.groq.com/openai/v1` | 無料枠。非常に高速。オープンモデル |
| Cerebras | `https://api.cerebras.ai/v1` | 無料枠。高速 |
| OpenRouter | `https://openrouter.ai/api/v1` | `:free` が付くモデルを指定 |
| GitHub Models | `https://models.github.ai/inference` | 1 リクエストあたり入力 8K トークンの上限があり、**ソース読解には使えません** |

モデル ID は頻繁に変わります。開始前に提供元のダッシュボードで現行の ID を
確認してください（Google なら
[モデル一覧](https://ai.google.dev/gemini-api/docs/models)）。誤った ID を
指定すると 404 になり、その旨が画面に出ます。

JSON モード（`response_format`）に対応していない提供元では、初回の 400 を
検知して自動的に外して送り直します。設定は要りません。

### 提供元を選ぶときに見る点

**入力の上限**が最も重要です。このアプリは小規模リポジトリのソースを丸ごと
送るので、1 リクエスト 10 万文字近くになることがあります。入力枠の小さい
提供元では、大きめのリポジトリで失敗します。

**無料枠の学習利用**にも注意してください。多くの提供元は無料枠の入力を
モデルの改善に使う権利を留保しています。公開リポジトリしか読まないなら
実害はありませんが、そのため `ALLOW_PRIVATE_REPOS` は既定で無効です。
自分がアクセスできるプライベートリポジトリにスターを付けていた場合、
明示的に許可しない限り要約は行われません。

## 人に渡して使ってもらう

一般公開はせず、渡した相手だけが使える形にしてあります。ログイン画面は
ありません。人ごとに URL を発行し、それを手渡します。

```bash
npm run invite -- add 田辺       # 招待リンクを発行する
npm run invite -- list           # 誰に渡したかを見る
npm run invite -- revoke <token> # 失効させる（読了記録は残る）
```

このコマンドは**動いているインスタンスに HTTP で話しかけます**（`BASE_URL` と
`ADMIN_TOKEN` が要ります）。デプロイ先にシェルで入る必要がないので、Render の
無料プランでも運用できます。

相手がその URL を一度開くと、トークンが HttpOnly cookie に移り、以後は
普通のページとして使えます。**リンクそのものが鍵**なので、公開の場所には
置かないでください。失効させれば次のリクエストから 401 になります。

読了の記録は**閲覧者 × 見ている GitHub アカウント**の組で分かれます。同じ
アカウントの本棚を 2 人が開いても、互いの「読了」は見えませんし、消せません。
要約のキャッシュだけは全員で共有します（同じ内容なら誰が開いても同じ結果に
なるため）。

`GITHUB_TOKEN` はサーバーを動かす人のものなので、**招待された人にプライベート
リポジトリは見せません**（`ALLOW_PRIVATE_REPOS` を有効にしない限り、一覧から
除外されます）。

### Render に置く

アプリは Render、状態は Turso（libSQL）です。ディスクを持たないので、
インスタンスが作り直されても招待リンクと読了記録は残ります。

```bash
# 1. Turso 側
turso db create gh-star-reader
turso db show gh-star-reader --url        # → TURSO_DATABASE_URL
turso db tokens create gh-star-reader     # → TURSO_AUTH_TOKEN
```

テーブルは初回アクセス時に作られるので、マイグレーションの手順はありません。

```bash
# 2. Render 側
#    render.yaml を Blueprint として読み込ませ、次を設定する
#      TURSO_DATABASE_URL  TURSO_AUTH_TOKEN
#      LLM_API_KEY         GITHUB_TOKEN
#      ADMIN_TOKEN         （自分で決めた長い文字列）

# 3. 招待を配る
BASE_URL=https://<your-app>.onrender.com ADMIN_TOKEN=… npm run invite -- add 田辺
```

`GITHUB_TOKEN` は実質必須です。未設定だと 60 リクエスト/時で、要約 1 件が
20 リクエスト前後を使うため、数人で触ればすぐ止まります。

無料プランは無通信が続くとインスタンスが停止し、次のアクセスで数十秒かかります。
`/api/health` は DB への疎通も見ているので、外形監視から叩けば起こし続けられます。

Vercel には置けません。要約の生成に 1 分近くかかることがあり、関数の実行時間に
収まらないためです。

## 設計方針

### スターには書き込みません

このツールを使っていると「読み終わったからスターを外す」という運用に
流れがちですが、意図的にその機能を持たせていません。

スターは私的なブックマークであると同時に、メンテナへの評価の表明であり、
GitHub のランキングやトレンドを支える公開シグナルでもあります。読了を
スターの削除で表すと、良かったリポジトリほど評価が撤回されるという
おかしなことになりますし、スターの記録（いつスターしたか）も失われます。

そこで役割を分けています。

```
GitHub 側 : スター = 追加専用の入力キュー（読み取り専用）
ローカル  : 既読・読了日 = 可変の個人状態
```

読み終わったリポジトリはこのアプリの中で畳まれるだけで、GitHub 側は
何も変わりません。

### 要約は開いたときに作ります

一覧の表示に LLM は使いません。スター 500 件を一括で要約すればコストも
待ち時間も許容できなくなりますが、実際に読むのはそのうちのごく一部です。
カードを開いたときに初めて生成し、結果をキャッシュします。

キャッシュキーは `owner/name@ツリーSHA` です。同じ内容なら再生成せず、
リポジトリが更新されれば SHA が変わって作り直されます。プライベート
リポジトリの要約はキャッシュに保存しません。

### 推薦はしません

意図的に持たせていない機能です。理由は 2 つあります。

ひとつは、マイナーなリポジトリには協調フィルタリングのシグナルが原理的に
存在しないこと。スター数が少ないリポジトリは、定義上、共起データが作れません。

もうひとつは、2026 年 7 月に GitHub が stargazers 一覧（あるリポジトリを
誰がスターしたか）の取得を管理者と共同編集者に限定したこと。ユーザー間の
共起を外部から計算する手段が実質的に失われています。

推薦が必要なら [GitRec](https://gitrec.gorse.io/) が既にあります。役割が
重ならないので、併用できます。

## 保存されるもの

libSQL の 4 テーブルです。ローカルでは `.data/gh-star-reader.db`（gitignore
済み）、デプロイ先では Turso。同じコードが両方を見ます。

| テーブル | 内容 | 消えたら |
| --- | --- | --- |
| `summaries` | 要約キャッシュ（全員で共有） | 作り直される |
| `languages` | 言語構成キャッシュ | 取り直される |
| `reading` | 読了記録（閲覧者 × GitHub アカウント） | **戻らない** |
| `invites` | 招待リンク | **戻らない**（配ったリンクが全部無効になる） |

## 制約

- スターは最大 1,000 件（10 ページ）まで読み込みます
- ソースコードまで読むのは、コードファイル 60 件以下かつ 4,000 KB 以下の
  リポジトリに限られます。それより大きいものはメタ情報だけで要約するため、
  内部構造についての記述は浅くなります
- デフォルトブランチ名にスラッシュが含まれるリポジトリではツリーを取得できません
- 単一ユーザー向けのローカルツールです。ファイルに直接書くため、そのままでは
  サーバーレス環境にデプロイできません
- 無料枠には 1 分あたり・1 日あたりのリクエスト上限があります。上限に達すると
  その旨が画面に出るので、しばらく待ってから再試行してください
- 無料枠は混雑時に 503 を返します。一時的なエラー（429・5xx）は最大 3 回まで
  自動で再試行し、それでも駄目なら理由を画面に出します。提供元との疎通だけを
  切り分けたいときは `bash scripts/check-llm.sh` を使ってください
